① 项目背景与目的

为什么做这个工具

很多内网 / 受限网络环境会出现这样的组合：git 协议不通（SSH 22、git:// 9418 被拦截）， 但 HTTPS 访问 api.github.com 是可行的。这种情况下命令行 git clone / git push 会长时间卡住或直接失败，而官方 GitHub Desktop 依赖本地 git 二进制，同样无法完成操作。

GitNest 的目标是把这个"半通"的网络条件利用起来：凡是能走 API 的事情走 API， 凡是必须落地文件的事情走本地文件系统与可选的本地 Git，从而在受限网络中依然能完成 浏览仓库、查看/编辑文件、提交、推送、拉取、分支管理这一整套日常协作动作。

设计目标

  • 网络容错：核心浏览与远程提交走 GitHub REST API（443 端口），不依赖 git 协议端口。
  • 真实本地 Git：本地仓库的提交 / 推送 / 拉取 / 分支操作使用系统 git，行为与命令行一致，历史真实可查。
  • 两条路并行：远程仓库可直接在线编辑并生成提交；本地仓库则享受完整的 Git 工作流。
  • 零后端：全部能力在 Electron 主进程内完成，不依赖自建服务，凭据只保存在本机配置中。
  • 可读可控：提交前可查看差异、推送前列出待推送提交、拉取前选择合并或变基，不做静默破坏性操作。
定位：面向受限网络下的开发者、以及希望用一个轻量客户端同时管理"在线仓库 + 本地仓库"的用户； 它不是 GitHub Desktop 的完整替代品，而是针对特定网络与工作流的补充工具。

② 快速开始

  1. 打开应用，在登录页选择一种登录方式（推荐 Personal Access Token，最快）。
  2. 登录后进入仓库列表，四个标签页：远程仓库 / 本地仓库 / 星标仓库 / 热门仓库。
  3. 点击任意仓库卡片进入详情；本地仓库会额外拥有「📝 本地改动」入口。
  4. 需要把线上仓库落到本地时，在远程仓库详情页点「⬇ 下载并初始化」。

③ 三种登录方式

三种方式最终都是拿到一个具有 repo 权限的 GitHub Token，区别在于获取 token 的过程。

方式需要准备适合场景有效期
Personal Access Token无（直接在网页生成）个人使用、最快自定义（可长期）
OAuth Device FlowOAuth App 的 Client ID不想手填 token，类 GitHub CLI 体验由 OAuth App 决定
Web OAuth（本地回调）OAuth App 的 Client ID + 回调地址标准网页授权流程由 OAuth App 决定

方式一：Personal Access Token（推荐起步）

  1. 打开 Fine-grained tokens（推荐）或 Classic tokens。
  2. Fine-grained：Token name 随意；Expiration 选期限；Resource owner 选个人账号； Repository access 选 All repositories（或指定仓库）； Permissions 中把 Contents 设为 Read and write（需要 Issues / PR 能力时再开对应项）。
  3. Classic：Note 随意，Expiration 自选，直接勾选 repo 整个大类。
  4. 点击 Generate token，复制生成的字符串（只显示一次）。
  5. 回到应用登录页，选择「Token 粘贴」，粘贴后点「🚀 登录并验证」。
注意：token 等同于账号密码，请勿提交到代码仓库或截图外发。若怀疑泄露，立即在 GitHub 设置中 Revoke。

方式二：OAuth Device Flow（设备码）

这是 GitHub CLI 使用的授权方式：应用拿到设备码，你在浏览器输入验证码确认，应用轮询获得 token。只需要 Client ID，不需要 Client Secret。

Step 1 · 注册 OAuth App

  1. 打开 Settings → Developer settings → OAuth Apps， 点 New OAuth App（组织账号则进入 Organization settings → Developer settings）。
  2. 填写：
    • Application name：随便填，例如 GitNest Local
    • Homepage URL：可填 https://github.com
    • Authorization callback URL：可填 https://github.com（设备码流程不使用回调）
  3. 创建后进入应用详情页，勾选 Enable Device Flow（关键步骤，不勾选会返回 device_flow_disabled）。
  4. 复制页面上的 Client ID（形如 Iv1.xxxxxxxxxxxxxxxx）。

Step 2 · 在应用内使用

  1. 登录页点右上角 ⚙️，把 Client ID 粘贴进去并保存。
  2. 选择「设备码」标签，点开始登录。
  3. 按提示在浏览器打开 github.com/login/device，输入应用显示的一次性验证码。
  4. 授权完成后应用会自动登录。
Scope 说明：应用默认申请 repo read:user（创建 / 更新仓库需要 repo 写权限）。 如需操作组织私有资源，请确保组织未限制第三方 OAuth App。

方式三：Web OAuth（本地回调）

标准网页授权：浏览器跳转 GitHub 授权页 → 授权后回调到本机端口 → 换取 token。

Step 1 · 配置 OAuth App 回调地址

  1. 同上进入 OAuth Apps → New OAuth App。
  2. Authorization callback URL 必须精确填写：http://127.0.0.1:8765/callback
  3. 创建后复制 Client ID；如需客户端密钥换取 token，可在同一页面生成 Client Secret。

Step 2 · 在应用内使用

  1. ⚙️ 中填入 Client ID 并保存。
  2. 选择「网页授权」标签，点击开始，浏览器会打开授权页。
  3. 点 Authorize 后，应用监听的 127.0.0.1:8765 收到回调，自动完成登录。
排查：若提示端口占用，请关闭占用 8765 的程序；若提示"换 token 失败"，通常是回调地址未与 OAuth App 配置完全一致， 或该应用未允许此流程，此时建议改用「设备码」方式。

④ 应用操作指南

仓库列表

  • 远程仓库：账号下的全部仓库（按更新时间排序）。
  • 本地仓库：已导入 / 已下载的本地目录，卡片显示文件数、目录数、待提交改动数。
  • 星标仓库：你 Star 过的仓库。
  • 热门仓库：按 Star 排序的高星项目。
  • 搜索：弹窗输入关键字回车，结果以「返回列表」回到原标签。
  • 刷新：强制重新拉取当前标签数据；标签切换与返回列表使用本地缓存，不会重复请求。
  • 新建 / 管理：新建仓库（可同时 clone 到本地）；管理面板可打开目录、移除本地记录、删除远程仓库（需输入仓库名二次确认）。

远程仓库详情

  • 文件：树形浏览、代码预览（跟随主题）、单文件历史、在线编辑并提交。
  • 提交 / 分支 / 标签 / 贡献者 / 活动：按需加载，切换标签时请求。
  • ⬇ 下载并初始化：下载分支 zip → 解压 → 初始化 Git → 关联远程 → 加入本地仓库列表。
  • 🔗 关联远程仓库：把本地目录与某个 GitHub 仓库绑定（支持下拉选择或手输）。

本地仓库 · 本地改动

  • 文件勾选暂存：左侧按「已暂存 / 未暂存 / 未跟踪」分组，勾选框切换暂存状态。
  • 差异查看：点击文件在右侧显示逐行差异。
  • 提交：填写摘要与描述（可自动生成），提交前有确认弹窗。
  • 推送：弹窗列出待推送提交与分支映射，确认后执行 git push。
  • 拉取 / 更新：选择合并（merge）或变基（rebase），可记住选择；拉取前提示本地未提交改动风险。
  • 分支：切换、新建、删除；顶部显示领先 / 落后提交数。

推送与拉取的行为差异

入口实际动作是否产生 .git 历史
远程仓库 · 下载并初始化下载 zip + 初始化 Git + 关联 origin是（初始化后）
远程仓库 · 在线提交GitHub Git Data API 合成提交是（在远端）
本地仓库 · 推送本地 git push（HTTPS 自动注入 token）是
本地仓库 · 更新本地 git pull [--rebase]是

⑤ 常见问题

  • 推送报 401 / Authentication failed：token 失效或权限不足，重新生成并勾选 repo 写权限；SSH 远程则检查本机密钥。
  • 推送被拒绝（non-fast-forward）：远端有新提交，先「更新（拉取）」再推送。
  • 拉取冲突：应用不会自动丢弃本地改动，请先提交或贮藏（stash）后再拉取。
  • 列表时间是旧的：列表使用缓存并在进入 / 切标签时加载；点「🔄 刷新」强制更新。若提交只存在于本地未推送，GitHub 侧不会变化。
  • 设备码提示 device_flow_disabled：OAuth App 未勾选 Enable Device Flow。
  • 图标显示为默认 Electron 图标：Windows 图标缓存未刷新，重启资源管理器即可。

⑥ 关于我们

GitNest 是一个面向受限网络环境的 GitHub 桌面客户端实践项目。目标不是复刻所有 Git 客户端功能， 而是在"git 协议不可用、API 可用"的现实约束下，给出一条能真正完成日常协作的路径。 项目采用主进程 + 渲染进程分层：所有网络与文件操作集中在主进程，渲染层只负责交互与展示， 便于审计、替换与二次开发。

技术栈

Electron 30 · Vue 3（Composition API）· Vite 5 · 原生 CSS 主题变量 · GitHub REST API v3 · 本地 Git CLI

架构

主进程承载 HTTP / 文件系统 / git 执行与 IPC；预加载层以 contextBridge 暴露最小接口；渲染层三个视图：登录、仓库列表、仓库详情。

数据与隐私

Token 与配置仅保存在本机用户目录（Electron userData），Token 使用系统凭据（Windows DPAPI / macOS Keychain）加密后落盘，不上传任何第三方服务器；所有请求直连 api.github.com。

版本与许可

当前版本 1.0.0，MIT License。支持 Windows x64（安装包 / 便携版 / 绿色目录三种形态）。

适用与不适用

适用于浏览、读写文件、提交、分支与推送等常规协作；不提供子模块、LFS 大文件、复杂冲突合并编辑器等高级能力。

反馈

⑦ 隐私政策

生效日期：2026 年 11 月 20 日 ｜ 开发者/运营方：Uaison（王淮森） ｜ 联系方式：752546024@qq.com

本隐私政策说明 GitNest（以下简称「本应用」）在收集、使用、存储和保护用户信息方面的做法。 本应用为纯客户端桌面工具，不依赖任何自建后端服务器，因此数据处理范围极其有限。

一、信息收集

本应用不主动收集、不上传任何用户数据到开发者或任何第三方服务器。具体而言：

  • 个人账户信息：不采集姓名、邮箱、手机号等个人身份信息。
  • 使用行为数据：无遥测（telemetry）、无用户行为分析、无崩溃上报。
  • 设备信息：不采集设备指纹、IP 地址、地理位置等信息。

运行过程中产生的所有数据均保存在您本机的用户目录下，不会离开您的设备。

二、GitHub Token 的处理

本应用需要访问 GitHub 仓库，因此会获取一个 GitHub Personal Access Token（或通过 OAuth 流程获取的访问令牌，以下统称「Token」）：

  • 获取方式：由您主动粘贴 Token，或通过 GitHub 官方 OAuth 流程（设备码 / 网页授权）获取，Token 由 GitHub 直接发放。
  • 存储方式：仅保存在本机用户目录的配置文件中，并使用操作系统级凭据加密（Windows DPAPI / macOS Keychain / Linux libsecret），加密后的存储前缀为 enc:v1:，无法在其他设备或其他用户账户下解密。
  • 使用方式：仅用于调用 GitHub REST API（api.github.com）及本地 Git 操作的远程鉴权（推送 / 拉取时注入到远程 URL，使用后即丢弃，不写入磁盘明文）。
  • 共享情况：Token 绝不会被发送给开发者或任何第三方，仅直连 GitHub 官方服务。
  • 删除方式：在应用内退出登录即清除本地 Token；或手动删除配置目录即可彻底清除；您也可随时在 GitHub 账户设置中吊销该 Token。

三、网络请求去向

所有网络请求均直连 GitHub 官方域名：

  • api.github.com —— GitHub REST API
  • github.com —— OAuth 授权与代码下载

Web OAuth 的回调地址为本机回环地址 http://127.0.0.1:8765/callback，仅在授权期间临时监听，授权完成后立即关闭端口，不对外暴露。

四、本地文件访问

  • 当您选择「导入本地仓库」或「下载并初始化」时，本应用会读写您指定目录中的文件与 Git 元数据（.git）。
  • 这些操作完全在本机进行，文件内容不会被上传。
  • 本应用不会读取或访问您未明确指定的目录。
